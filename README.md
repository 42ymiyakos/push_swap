# push_swap

## Description (概要)

**push_swap** は、42のカリキュラムで開発したC言語のプログラムです。2つのスタック（`a` と `b`）と限られた操作だけを使い、重複のない整数列を昇順に並べ替えます。ソートに必要なスタック操作を標準出力に表示し、その操作回数をできるだけ少なくすることを目指します。

この実装では、入力の並び方によって適切なソート手法が異なることに着目し、**Simple・Medium・Complex・Adaptive** の4つの戦略を用意しました。デフォルトのAdaptive戦略では、初期入力の乱雑度（disorder）を測定し、その値に応じて手法を選択します。

スタックには双方向連結リストを使用しています。また、ソート前に整数を順位へ正規化するため、元の値の大きさや符号に関係なく `0` から `n - 1` の範囲で処理できます。

## Instructions (使用方法)

### Compilation (コンパイル)

リポジトリのルートで以下を実行します。

```sh
make
```

生成される実行ファイル名は `push_swap` です。標準的なクリーンアップ用ターゲットは次のとおりです。

```sh
make clean
make fclean
make re
```

### Execution (実行例)

```sh
./push_swap 3 2 1
./push_swap "5 1 4 2 3"
./push_swap --adaptive 5 1 4 2 3
./push_swap --simple 5 1 4 2 3
./push_swap --medium 5 1 4 2 3
./push_swap --complex 5 1 4 2 3
```

| オプション | 動作 |
| --- | --- |
| `--simple` | 最小値を取り出していくソートを指定 |
| `--medium` | チャンクベースのソートを指定 |
| `--complex` | 2進数を使ったLSD基数ソートを指定 |
| `--adaptive` | 乱雑度に基づいて戦略を選択（デフォルト） |
| `--bench` | ベンチマーク情報を標準エラー出力へ表示するモードを指定 |

ソート操作は**標準出力**に1行ずつ表示します。整数として解釈できない入力、32ビット符号付き `int` の範囲外の数値、重複する数値は不正な入力とみなし、**標準エラー出力**に `Error` を出力します。引数がない場合は何も表示しない仕様です。

操作回数の確認例：

```sh
./push_swap 4 67 3 87 23 | wc -l
```

42から提供されるチェッカーがある場合の検証例：

```sh
ARG="4 67 3 87 23"
./push_swap --complex $ARG | ./checker_linux $ARG
```

## Operations (使用できる操作)

| 操作 | 内容 |
| --- | --- |
| `sa`, `sb` | スタック `a` または `b` の先頭2要素を交換 |
| `ss` | `sa` と `sb` を同時に実行 |
| `pa` | `b` の先頭要素を `a` の先頭へ移動 |
| `pb` | `a` の先頭要素を `b` の先頭へ移動 |
| `ra`, `rb` | スタックを回転させ、先頭要素を末尾へ移動 |
| `rr` | 両方のスタックを同時に回転 |
| `rra`, `rrb` | 逆回転させ、末尾要素を先頭へ移動 |
| `rrr` | 両方のスタックを同時に逆回転 |

初期状態では `a` にすべての入力値が入り、`b` は空です。最終的には `a` にすべての値が昇順で格納され、`b` が空である必要があります。

## Algorithms (アルゴリズムと設計上の判断)

以下の計算量は、通常のC言語の補助関数の実行時間ではなく、課題の指定に従い**生成されるpush_swap操作の回数**を基準としています。

### 1. Simple — 最小値の取り出し `O(n²)`

Simple戦略では、スタック `a` に残っている最小値を探し、`ra` と `rra` のうち移動回数が少ない方向で先頭に持ってきてから `b` へ移します。`a` の要素が3個以下になったら直接ソートし、`b` に退避した値を `a` へ戻します。

**採用理由：** 動作を追いやすく、特に小規模な入力や比較的整列した入力で理解しやすい手法であり、二次計算量の基準となるアルゴリズムとして利用できます。

**操作回数の上界：** 1回の最小値取り出しに最大 `O(n)` 回の回転が必要で、取り出しは最大 `O(n)` 回です。したがって、総操作回数は `O(n²)` です。2つのスタック以外にソート自体が使用する作業領域は `O(1)` で、操作バッファは後述のとおり別に扱います。

### 2. Medium — チャンクソート `O(n√n)`

Medium戦略では、正規化済みの値の範囲を、幅がおよそ `√n` のウィンドウに区切ります。スタック `a` を走査し、対象範囲に入る値を `b` へ移動します。その際、小さい値を配置するために `b` を回転することがあります。その後、`b` の最大値を繰り返し探し、回転回数の少ない方向で先頭へ移動して `a` に戻します。

**採用理由：** 個々の最小値を毎回取り出す方法と、各ビットに対してパスを行うRadixソートの中間に位置する方法です。値をまとまりごとに扱うことで探索範囲を絞り、スタック操作だけでソートを進められます。

**操作回数の上界：** 範囲の幅をおよそ `√n` にするため、チャンク数はおよそ `√n` 個です。

- **分配フェーズ：** 1つのチャンクの値をすべて `b` へ移すまでに、`a` の回転は最大で約1周（`n` 回）です。チャンクが `√n` 個あるので、回転は合計 `O(n√n)` 回です。これに `pb` と `rb` がそれぞれ最大 `n` 回加わります。
- **回収フェーズ：** チャンクを順番に積んでいるので、`b` の最大値は常に、残っている中で最も大きいチャンクに含まれます。そのチャンクは `b` の先頭側か末尾側の約 `√n` 要素の中にあるため、最大値を先頭へ持ってくる回転は1要素あたり `O(√n)` 回です。`n` 要素分で `O(n√n)` 回、これに `pa` が `n` 回加わります。

したがって、総操作回数は `O(n√n)` です。ソート自体が使う作業領域はチャンクの境界値などの `O(1)` だけで、操作バッファは後述のとおり別に扱います。

### 3. Complex — 2進LSD基数ソート `O(n log n)`

Complex戦略では、正規化した順位に対して下位ビットから順に処理するLSD（Least Significant Digit）Radix Sortを使用します。各ビットについて、スタック `a` の元の要素数だけ次の操作を実行します。

1. 対象ビットが `0` の場合は `pb` を実行する。
2. 対象ビットが `1` の場合は `ra` を実行する。
3. 1回の走査が終わったら、`b` の要素をすべて `pa` で `a` に戻す。

最大順位 `n - 1` を表現するために必要なビット数だけ、この処理を繰り返します。

**採用理由：** 大量の要素や乱雑度が高い入力でも操作回数の増え方を予測しやすいからです。順位への正規化により、ビット数は元の整数の絶対値ではなく要素数 `n` で決まります。

**操作回数の上界：** 各ビットにつき最大 `n` 回の `ra` / `pb` と最大 `n` 回の `pa` を実行します。`n > 1` ではビットごとの走査回数が `⌈log₂ n⌉` 回なので、総操作回数は最大 `2n⌈log₂ n⌉` 回、すなわち `O(n log n)` です。

### 4. Adaptive — 乱雑度に応じた戦略選択

Adaptive戦略では、まず既に整列済みか確認します。また、昇順に整列した列を円環状に回転しただけの入力も検出します。隣り合う要素が降順になる箇所がちょうど1か所で、先頭の値が末尾の値より大きい場合は、`ra` または `rra` の少ない方だけで元の昇順に戻せます。

それ以外の入力には、乱雑度に基づいて次の戦略を選びます。

| 初期乱雑度 | 使用する戦略 | 操作回数の計算量目標 |
| --- | --- | --- |
| `0 ≤ d < 0.2` | Simple | `O(n²)` |
| `0.2 ≤ d < 0.5` | Medium | `O(n√n)` |
| `0.5 ≤ d ≤ 1` | Complex | `O(n log n)` |

**閾値の根拠：** `0.2` と `0.5` は課題で指定された境界です。低・中・高乱雑度を区切るために使用しており、実験によって最適であると証明した値ではありません。

**各領域の計算量：** Adaptive戦略の操作回数は、選択された内部アルゴリズムの上界に従います。整列済みなら操作回数は0回です。回転だけで整列できる場合は最大 `⌊n/2⌋` 回の操作で済むため、どの乱雑度領域の要求上界も超えません。乱雑度の計算にはC言語で `O(n²)` 回の比較が必要ですが、**push_swap操作は1回も生成しません**。この区別が、課題の操作回数モデルでは重要です。

### 乱雑度（Disorder）の計算

乱雑度は、入力列の全ペアのうち、順序が逆転しているペアの割合です。

\[
\mathrm{disorder} = \frac{\#\{(i,j) \mid i < j \text{ and } a_i > a_j\}}{n(n-1)/2}
\]

`n < 2` の場合は `0` と定義します。昇順なら乱雑度は `0`、完全な降順なら `1` です。実装では**スタック操作を始める前**にすべてのペアを調べており、課題指定の計算方法と一致しています。

### 順位への正規化（Rank Normalization）

ソート開始前に、各値を「自分より小さい入力値の個数」へ置き換えます。例えば次のようになります。

```text
元の値:    40  -7  12  99
正規化後:   2   0   1   3
```

これによって大小関係を保ったまま、重複のない整数列を `0 ... n - 1` に変換できます。現在の実装は各値を他の値と比較して順位を求めるため、C言語での処理時間は `O(n²)`、一時的なメモリ使用量は `O(n)` です。この前処理もpush_swap操作は生成しません。

### スタック構造と操作バッファ

2つのスタックはいずれも、`head`・`tail`・`size` を保持する双方向連結リストです。配列の要素全体をコピーすることなく、ポインタのつなぎ替えで交換・プッシュ・回転を実現できます。

スタック操作は共通の実行経路を通ります。まずスタックに操作を適用し、列挙型の値として可変長バッファに追加し、最後に順番どおり出力します。バッファの容量が足りなくなった場合は倍増させます。出力時にはベンチマーク用に操作の種類ごとの回数も集計します。

生成した操作数を `k` とすると、操作バッファのメモリ使用量は `O(k)` です。スタックノードと正規化用の作業領域は `O(n)` です。これらの領域計算量は、前述の操作回数の計算量と区別します。
